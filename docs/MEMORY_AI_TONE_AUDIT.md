# 记忆与「AI 味」专项审计（2026-10-20）

> 目的：回答三个问题——她的记忆到底存在哪、上下文怎么拼、为什么会有「AI 味」和「记不住」。
> 方法：代码走查 + 真实 DeepSeek 对话压力测试（临时数据目录，不污染线上）+ 修复前后对比。
> 结论先行：**记忆"存了"但"不会用"是主要问题；AI 味主要来自分段/套话/编造，而不是模型本身。**

---

## 0. 一页结论

| 问题 | 根因 | 本轮处理 |
|---|---|---|
| 5 轮前说过的「项目」记不住 | T2 检索把「她上一轮说不知道」的记忆排到最前（**自我强化遗忘**）；没有结构化用户事实兜底 | 新增**结构化用户事实层**（后台 LLM 抽取 + SQLite + 每轮注入），实测项目可答对 |
| 记忆"存了但不用" | 只靠 T2 向量/关键词检索，无事实层、无画像块；语义 embedding 未启用（无 Qwen Key） | 事实层已加；语义检索需 Key（见待办） |
| 早上 10 点发"今天的晚霞" | 发图逻辑曾按小时硬过滤 | 已改为「拍摄时间 vs 分享时间」模型（昨天/以前/今天） |
| 消息以「，」结尾、碎片化 | burst/流式把逗号当分段点，且保留尾部标点 | 已修：只按句末分段，剥掉尾部软标点 |
| "确实呢""啊这"套话、被问就反问"考我" | 模型默认的助手式应答惯性 | prompt 增加反套话/反反问规则 |
| 编造没发生过的往事（"上次给你买奶茶"） | 没有 grounding 约束，模型自由发挥 | prompt 增加"不许编造具体往事"铁律 |
| 上下文重复 | 最近 8 条消息同时出现在聊天历史和 shortTermContext | 已移除 shortTermContext 重复注入 |

## 2. 她的记忆到底存在哪

所有数据默认在项目 `data/`（可用 `KAREN_DATA_DIR` 覆盖），多用户按 owner 隔离。

| 层 | 位置 | 线上实际数据（2026-10-20） | 是否进 prompt |
|---|---|---|---|
| T0 会话 | `data/小雅-session.json` | 86 条消息（滚动窗口 200） | ✅ 最近 15 条直接进 messages；更早 10 条压缩成"聊过的大概" |
| T1 人格快照 | `t1_snapshots`（SQLite） | 42 条（情绪/亲密度/负债/摘要） | ❌ 当前没有注入（潜在优化点） |
| T2 情节记忆 | `t2_episodes`（SQLite）+ `t2_fts` + `t2_vec` | 88 条：chat 42 / 独白 42 / 日记 4 | ✅ 每轮检索 top 8，经 RRF 后作为「你突然想起来」注入 |
| T3 长期摘要 | 写回 `t2_episodes(source=t3_summary)` | 0 条（未到阈值） | ✅ 通过 T2 检索间接生效 |
| 用户事实 | `user_facts`（SQLite，本轮新增） | 重启后随对话累积 | ✅ 每轮以「你确定记得的关于对方的事」注入 |
| 她眼中的你 | `persona-state-小雅.json` → `herView` | 1 条（已生成） | ✅ 拼进「你和对方的关系」 |
| 人格/关系/情绪 | `persona-state-小雅.json` | 亲密度 3.21、9 个关系事件、叙事阶段 `noticing` | ✅ 结构化标签注入 |
| 内心独白 | T2（`source=internal_monologue`） | 42 条 | ❌ 不直接注入（只做检索/演化材料） |
| 使用成本 | `llm_usage`（SQLite） | 只统计 chat/chatStream | — |

**每轮上下文拼装顺序（以 QQ 流式主路径为例）**：
1. 静态人设块（约 1.5–2k tokens，命中缓存）
2. 动态状态标签（情绪/负债/亲密度/时段/模式）
3. 行为脚本 + 关系块 + herView + 纠正层
4. 叙事弧线/风格参考/热点/中断提示/冲突提示/危机提示
5. **用户事实块**（本轮新增，≤20 条）
6. RAG 记忆（T2 top 8）
7. 最近消息历史（最近 15 条）+ 更早消息摘要

> 本轮删掉了 `shortTermContext`（把最近 8 条再注入一遍），此前它和「最近 15 条历史」重复，既浪费 token 又强化重复表达。

## 3. 压力测试：她真的记得吗？

### 方法
临时 `KAREN_DATA_DIR`，真实模型，9 轮对话：
先告诉她「我叫林哲 / 杭州产品设计 / 养橘猫叫团子 / 在做咖啡品牌包装项目」，插入 2 轮闲聊后，连续问 4 个记忆问题。

### 修复前（仅 T2 检索）

| 问题 | 回答 | 结果 |
|---|---|---|
| 我叫什么 | 林哲啊，怎么突然这么问 | ✅ |
| 我在哪工作 | 杭州，产品设计 | ✅ |
| 我的猫叫什么 | 团子，橘猫，特别能吃 | ✅ |
| 我在做什么项目 | **这个我还真不知道**，你之前说过吗 | ❌ |

**为什么漏**：单独检索「咖啡品牌包装」其实能命中（relevance 1.0），但用「我最近在做什么项目」检索时，排第一的是**上一轮她回答"不知道"的那条记忆**（问题文本相同），把真正的项目事实挤掉 → 她再次说"不知道"，形成自我强化遗忘。

### 修复后（T2 检索 + 结构化事实层）

| 问题 | 回答 | 结果 |
|---|---|---|
| 我叫什么 | 林哲啊，才一个月就考我，我记性没那么差 | ✅ |
| 我在哪工作 | 杭州 做产品设计的，还做咖啡包装，你今天是抽查吗 | ✅ |
| 我的猫叫什么 | 团子，橘猫，胖的那只 | ✅ |
| 我在做什么项目 | **咖啡包装啊，刚还说累呢** | ✅ |

后台自动抽取到的事实（实测）：
`name=林哲`、`city=杭州`、`job=产品设计`、`project=咖啡品牌包装项目`、`pet=养了一只橘猫叫团子`、`plan=晚上煮面吃`。

> 说明：事实层不是取代 T2，而是给「稳定事实」一个确定可靠的通道；T2 继续负责「发生过什么/情绪记忆」。

## 4. 「AI 味」到底来自哪

对 2 组真实输出做模式检查，AI 味主要不是"模型太笨"，而是工程细节：

| 现象 | 证据（修复前） | 处理 |
|---|---|---|
| 消息以逗号结尾 | 「啊这，」「跟我上次一模一样 确实呢 记得躲一下，」 | burst 分条剥掉尾部 `，、；`；流式不按逗号分条 |
| 助手式套话 | 「确实呢」「啊这」「哈哈是吗」 | prompt 明令禁用；禁重复上一轮开头 |
| 被问记忆就防御 | 连续三次「考我 / 抽查 / 怎么突然问」 | prompt 要求「直接答 + 只轻轻吐槽一次」，并点名禁用词 |
| 编造共同经历 | 全新会话里说「上次说想喝奶茶，你第二天就带来了」（根本没发生） | prompt 增加 grounding 铁律：只引用事实/上下文/记忆块 |
| 碎片/空行 | 模型输出连续空行，CLI 显示空行 | 渲染前压缩连续空行 |
| 过度自我分析 | 「其实、好像、感觉」高频开头 | prompt 限制 |
| 重复回应 | 多轮同一套「累不累/吃饭没」 | 待办：跨轮回复去重（见 §6） |

修复后同一类对话（实测）：
> 「又是加班啊… … 我跟你说，上班真的会把人熬干。昨天我看那个调休的热搜，笑死，越调越累。」
> 「那也行。躺着最舒服了，我休息天也是躺一天。猫还踩我脸上叫我起床。」
（不再有逗号碎片、确实呢、考我）

## 6. 还没做 / 效果仍差的功能点（按优先级）

### P0（直接影响"像人/记得住"）

1. **语义检索未启用**：没有 Qwen Key，只有 n-gram + BM25；同义表达（"项目" vs "包装案"）会漏。
   - 行动：配置 `QWEN_VL_API_KEY` → 自动走语义 + BM25 混合；或上本地 embedding（M2）。
2. **跨轮回复去重**：她可能连续多轮用同一句式（"是不是又没好好吃饭"）。
   - 行动：把最近 3 条她的回复加入 prompt 的"不要重复"清单；或后处理降重。
3. **T1 未使用**：42 条情绪/关系快照完全没进 prompt；长期关系缺少"最近情绪弧线"。
   - 行动：把最近 3–5 条 T1 压缩成一句"最近几天你们的状态"，注入关系块。
4. **记忆评测缺失**：目前靠人工抽查；没有可复现的金标集。
   - 行动：固定 20 条事实 + 20 个问题，脚本跑 recall@k；每次改动对比。

### P1（表达与记忆深度）

5. **T3 压缩未跑起来**：80 条才触发，线上 0 条；旧对话会一直停留在 T2 原始事件里。
   - 行动：降低阈值/改按 token 预算触发；压缩后做质量抽检。
6. **事实抽取的冲突消解**：同 key 直接覆盖，换工作/换城市正确，但"以前/现在"的时间关系没保留。
   - 行动：facts 加 `valid_from/valid_to` 或"历史值"列表。
7. **记忆召回没有"时间感"**：注入的 T2 都是 `[对话]` 文本，没有"多久以前"。
   - 行动：注入时加相对时间（"三天前"），她才能自然说"你上次说…"。
8. **Web 控制台看不到事实/记忆命中**：只有最近记忆列表和搜索。
   - 行动：控制台加"她确定记得的事实"和"本轮命中记忆"面板。

### P2（产品完善）

9. 群聊/私聊 state 共用；群聊未接发图/贴纸。
10. 语音 ASR；多实例托管；年龄门从提示升级为确认。
11. 成本统计不含事实抽取/独白/T3 等旁路调用（`cost_today` 是下限）。
