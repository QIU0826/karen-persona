# 记忆与「AI 味」专项审计（2026-10-20）

> 目的：回答三个问题——她的记忆到底存在哪、上下文怎么拼、为什么会有「AI 味」和「记不住」。
> 方法：代码走查 + 真实 DeepSeek 对话压力测试（临时数据目录，不污染线上）+ 修复前后对比。
> 结论先行：**记忆"存了"但"不会用"是主要问题；AI 味主要来自分段/套话/编造，而不是模型本身。**

## 0. 一页结论

| 问题 | 根因 | 本轮处理 |
|---|---|---|
| 5 轮前说过的「项目」记不住 | T2 检索把「她上一轮说不知道」的记忆排到最前（**自我强化遗忘**）；没有结构化用户事实兜底 | 新增**结构化用户事实层**（后台 LLM 抽取 + SQLite + 每轮注入），实测项目可答对 |
| 记忆"存了但不用" | 只靠 T2 向量/关键词检索，无事实层、无画像块；语义 embedding 未启用（无 Qwen Key） | 事实层已加；检索层加 **DeepSeek 候选重排**（默认开启，20 条金标 recall@1 55%→95%，见 §3.1）；真语义向量仍需 Qwen Key/本地模型 |
| 早上 10 点发"今天的晚霞" | 发图逻辑曾按小时硬过滤 | 已改为「拍摄时间 vs 分享时间」模型（昨天/以前/今天） |
| 消息以「，」结尾、碎片化 | burst/流式把逗号当分段点，且保留尾部标点 | 已修：只按句末分段，剥掉尾部软标点 |
| "确实呢""啊这"套话、被问就反问"考我" | 模型默认的助手式应答惯性 | prompt 增加反套话/反反问规则 |
| 编造没发生过的往事（"上次给你买奶茶"） | 没有 grounding 约束，模型自由发挥 | prompt 增加"不许编造具体往事"铁律 |
| 上下文重复 | 最近 8 条消息同时出现在聊天历史和 shortTermContext | 已移除 shortTermContext 重复注入 |
| 跨轮复读（连续几轮同开头/同一句） | 模型看不到自己上一轮具体说了什么，静态 prompt「别重复开头」约束不住 | 新增 `src/persona/anti-repetition.ts`：每轮注入最近开头词反重复块 + 回复后检测记日志；真实 A/B 见 §4.1 |
| 自然问句 FTS 检索 0 命中 | 逐字 token 用 FTS5 默认 AND，自然问句要求每个字都出现在同一条记忆 | `searchEpisodesByFts` 改 OR + BM25 IDF 排序：T2 recall@1 20%→50%、@3 35%→75%、@8 40%→85% |
| QQ 私聊（流式）没注入用户事实 | 事实层只接在非流式管线，流式 `fullSystem` 漏了事实块 | 已补：流式注入事实块 + 反重复块，单测覆盖（此前文档误写为「流式/非流式都生效」） |

**每轮上下文拼装顺序（以 QQ 流式主路径为例）**：
1. 静态人设块（约 1.5–2k tokens，命中缓存）
2. 动态状态标签（情绪/负债/亲密度/时段/模式）
3. 行为脚本 + 关系块 + herView + 纠正层
4. 叙事弧线/风格参考/热点/中断提示/冲突提示/危机提示
5. **用户事实块**（≤20 条）
6. **反重复提示**（最近 2–3 条回复的**开头词**；不只给整句，避免模型照抄自己）
7. RAG 记忆（T2 top 12 经 DeepSeek 重排 → 注入 top 8）
8. 最近消息历史（最近 15 条）+ 更早消息摘要

> 本轮删掉了 `shortTermContext`（把最近 8 条再注入一遍），此前它和「最近 15 条历史」重复，既浪费 token 又强化重复表达。

## 3. 压力测试：她真的记得吗？

### 方法
临时 `KAREN_DATA_DIR`，真实模型，9 轮对话：
先告诉她「我叫林哲 / 杭州产品设计 / 养橘猫叫团子 / 在做咖啡品牌包装项目」，插入 2 轮闲聊后，连续问 4 个记忆问题。

### 修复前（仅 T2 检索）

| 问题 | 回答 | 结果 |
|---|---|---|
| 我叫什么 | 林哲啊，怎么突然这么问 | ✅ |
| 我在哪工作 | 杭州，产品设计 | ✅ |
| 我的猫叫什么 | 团子，橘猫，特别能吃 | ✅ |
| 我在做什么项目 | **这个我还真不知道**，你之前说过吗 | ❌ |

**为什么漏**：单独检索「咖啡品牌包装」其实能命中（relevance 1.0），但用「我最近在做什么项目」检索时，排第一的是**上一轮她回答"不知道"的那条记忆**（问题文本相同），把真正的项目事实挤掉 → 她再次说"不知道"，形成自我强化遗忘。

### 修复后（T2 检索 + 结构化事实层）

| 问题 | 回答 | 结果 |
|---|---|---|
| 我叫什么 | 林哲啊，才一个月就考我，我记性没那么差 | ✅ |
| 我在哪工作 | 杭州 做产品设计的，还做咖啡包装，你今天是抽查吗 | ✅ |
| 我的猫叫什么 | 团子，橘猫，胖的那只 | ✅ |
| 我在做什么项目 | **咖啡包装啊，刚还说累呢** | ✅ |

后台自动抽取到的事实（实测）：
`name=林哲`、`city=杭州`、`job=产品设计`、`project=咖啡品牌包装项目`、`pet=养了一只橘猫叫团子`、`plan=晚上煮面吃`。

> 说明：事实层不是取代 T2，而是给「稳定事实」一个确定可靠的通道；T2 继续负责「发生过什么/情绪记忆」。

### 3.1 检索重排（2026-10-20 补充）

真语义 embedding 需要外部 Key/模型，先用 DeepSeek Flash 对检索候选做一次相关性重排来补精度
（详细报告：[docs/SEMANTIC_BOOST_EVAL.md](SEMANTIC_BOOST_EVAL.md)，实现 `src/data/retrieval-boost.ts`）：

| 方案（同一 20 条金标） | recall@1 | recall@3 | recall@8 | 每轮额外成本/延迟 |
| --- | ---: | ---: | ---: | --- |
| 基线（n-gram + FTS5 OR → RRF） | 55% | 80% | 85% | — |
| 仅查询改写 | 50% | 80% | 90% | ~794ms |
| **仅候选重排（生产默认）** | **95%** | **95%** | **95%** | ~664ms，~¥0.00025/轮 |
| 改写 + 重排 | 90% | 90% | 90% | ~1.5s |

结论：只加一次重排收益最大；改写反而降精度（不采用）。任何异常/超时（默认 2.5s）/关闭开关
（`KAREN_SEMANTIC_BOOST=off`）都会降级回原顺序，不影响回复。**这不是真语义**，真向量仍可作为下一步。


## 4. 「AI 味」到底来自哪

对 2 组真实输出做模式检查，AI 味主要不是"模型太笨"，而是工程细节：

| 现象 | 证据（修复前） | 处理 |
|---|---|---|
| 消息以逗号结尾 | 「啊这，」「跟我上次一模一样 确实呢 记得躲一下，」 | burst 分条剥掉尾部 `，、；`；流式不按逗号分条 |
| 助手式套话 | 「确实呢」「啊这」「哈哈是吗」 | prompt 明令禁用；禁重复上一轮开头 |
| 被问记忆就防御 | 连续三次「考我 / 抽查 / 怎么突然问」 | prompt 要求「直接答 + 只轻轻吐槽一次」，并点名禁用词 |
| 编造共同经历 | 全新会话里说「上次说想喝奶茶，你第二天就带来了」（根本没发生） | prompt 增加 grounding 铁律：只引用事实/上下文/记忆块 |
| 碎片/空行 | 模型输出连续空行，CLI 显示空行 | 渲染前压缩连续空行 |
| 过度自我分析 | 「其实、好像、感觉」高频开头 | prompt 限制 |
| 重复回应 | 多轮同一套「累不累/吃饭没」 | 已修：每轮注入最近开头词反重复块（默认只给开头片段）；回复后检测相似度并记 `[重复]` 日志 |
| 提供整句反而诱发照抄 | A/B 实验：把最近 3 条完整回复放进 prompt 后，模型开始把自己上一轮的话原样拼进新回复（复读对 0→0.33、平均相似度 0.056→0.125） | 默认改为 `openers` 模式（只给开头 3 字），复读对 0、平均相似度 0.027（低于不注入）；`full` 仅保留给评测对照 |

修复后同一类对话（实测）：
> 「又是加班啊… … 我跟你说，上班真的会把人熬干。昨天我看那个调休的热搜，笑死，越调越累。」
> 「那也行。躺着最舒服了，我休息天也是躺一天。猫还踩我脸上叫我起床。」
（不再有逗号碎片、确实呢、考我）

### 4.1 跨轮重复 A/B（真实模型，2026-10-20）

脚本：`src/eval/repetition-eval.ts`（临时数据目录；baseline / openers / full 三组，每组跑 3 轮，
每轮 6 句故意重复的问句：「在干嘛 / 在干嘛呢 / 你在干嘛呀 / 我好累啊 / 我真的很累 / 今天真的好累」）：

| 组 | 说明 | 复读对（相邻） | 连续同开头 | 平均相似度 | 最高相似度 | 套话命中 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| baseline | 关闭反重复注入 | 0 | 0 | 0.056 | 0.132 | 0.333 |
| **openers（生产默认）** | 只注入最近开头词 | **0** | **0** | **0.027** | **0.086** | 0.333 |
| full | 回放最近 3 条完整短句 | 0.333 | 0.667 | 0.125 | 0.492 | 0.667 |

结论（如实）：
- **不能把整句回放给模型**——小模型会直接照抄自己上一轮的话（full 组反而更重复），这也是默认选 `openers` 的原因；
- 只给开头片段时，词法重复为 0、平均相似度比不注入还低（0.027 vs 0.056），说明「提醒换开头」有效；
- 但**套话命中率两组都是 0.333**：反重复只解决「字面复读」，解决不了「换汤不换药」的句式复读（例如每轮都来一句「是不是没睡好」）。
  语义级重复检测/改写仍是待办（见 §6 P2）。
- 样本小（3 轮 × 6 句）、模型随机性存在，本表只用于方向判断，不作为对外指标。
