## 3. 发现的问题与修复

### 3.1 事实抽取质量（真实 bug，已修）

首轮抽出：
```
city=嘉兴(❌ 角色老家人设，不是用户说的)
job=上班族(❌ 模糊，用户说的是「产品设计」)
pet=养了一只猫(❌ 丢了名字/颜色，用户说的是「橘猫叫团子」)
preference=休息日能在床上瘫一整天(❌ 用户没说过，推断)
name=林哲 ✅ / project=咖啡品牌包装项目 ✅ / important_date=周三去云南 ✅
```

修复（`src/data/user-facts.ts`）：
1. **prompt 加固**：只从「用户说」提取、禁止从角色回复提取（点名「角色说老家嘉兴 ≠ 用户城市」）、每个值必须在用户原话有依据、保持细节（宠物带名字/种类）、禁止「上班族」这种模糊职业、禁止把「上班/加班/累」推断成工作、一次性闲聊不提取成偏好。
2. **确定性接地校验**（LLM 不听话时的兜底）：`isFactGroundedInUserText`——值的任意二字片段/英文数字 token 必须在用户原话里出现，否则丢弃；`groundFacts` 过滤并记录丢弃数。

**修复后同场景实测**：
```
FACTS: project=咖啡品牌包装项目 | pet=橘猫叫团子 | city=杭州 | job=产品设计 | name=林哲
GROUNDING OK（无嘉兴/上班族/推断偏好）
```

### 3.2 记忆防御话术（prompt 禁令仍会漏，已加确定性守卫）

首轮 T9 真实出现：「接着 林哲啊 才聊过就忘，**我记性没那么差**」。
修复：新增 `src/persona/reply-guard.ts` 的 `stripMemoryDeflection`——出站前删掉含
「考我/查岗/抽查/我记性没那么差」的分句（保留同句其他内容；整条都是这种话术时退化为「嗯」），
三条管线（普通/流式/主动）都接入，并记录 `[去AI味]` 日志。单测 6 条。

### 3.3 检索重排的无效调用（性能，已优化）

30 轮里 10 轮日志出现「重排无有效输出」——候选太少（1–2 条）或模型返回空数组时，仍花一次调用/约 1s。
修复：候选 `<3` 条直接跳过重排（`MIN_BOOST_POOL_SIZE=3`），省调用与延迟；质量不受影响（1–2 条候选排序没有意义）。
剩余「空数组」情况属正常（模型认为都不相关），保留原顺序。

### 3.4 指标误报（harness 自身）

首轮「括号动作 1 轮」是颜文字 `(=^･ω･^=)` 被 ASCII 括号规则误判；已把规则收窄为中文括号/方括号。

## 4. 局限（如实）

- CLI 非流式延迟 ≠ QQ 体感：QQ 是流式逐条发送，首条到达更早；本表用于横向对比，不是用户感知承诺。
- 单次 30 轮运行、模型温度随机；记忆/事实类问题已用确定性断言 + 单测锁定，延迟/相似度数字有波动。
- 成本按项目峰谷价估算（节假日按工作日近似）。
