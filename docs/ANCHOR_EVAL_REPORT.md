# 锚点复筛评测报告

> 评测对象：`src/schedule/anchor-refine.ts` 的「该记 / 不该记」判断（生产同一份 prompt）。
> 金标集：`src/eval/anchor-gold.json`（30 条：该记 17 / 不该记 13，覆盖约定、生病、换工作、
> 搬家、冲突、和好、秘密、表白、第一次、边界越界、家庭事件、长期计划，以及天气/抱怨/玩笑/
> 问候/报备/表情/单次夸奖等不该记的对照）。
> 跑法：`node node_modules/tsx/dist/cli.mjs scripts/anchor-eval.ts [--offline] [--write-report]`（一次约 ¥0.003）。

## 四次独立运行（同一份代码）

| 运行 | 准确率 | 精确率 | 召回率 | kind | 混淆 |
|---|---:|---:|---:|---:|---|
| 1 | **100%** | 100% | 100% | 94.1% | TP17 / FP0 / FN0 / TN13 |
| 2 | **100%** | 100% | 100% | 94.1% | TP17 / FP0 / FN0 / TN13 |
| 3 | 90.0% | 100% | 82.4% | 78.6% | TP14 / FP0 / FN3 / TN13 |
| 4 | 96.7% | 100% | 94.1% | 88.2% | TP16 / FP0 / FN1 / TN13 |

### 怎么读这组数

- **精确率四次都是 100%**：模型从不把"不该记的"塞进锚点——这是最要紧的方向，
  因为误建锚点会污染长期记忆且难以清除；漏记只是少记一点，代价小得多。
- **召回 82–100%** 有波动：第 3 次漏了 3 条（其中一条是「越界要照片」的边界事件，
  见下方误判明细），说明"冲突/越界"这类没有明确关键词的事件容易被判成不值得记。
- **kind 79–94%**：类型判断不稳定（例如把"不吃辣"判成 secret），
  但 kind 只影响注入时的措辞标签，不影响"记不记得"，优先级低于召回。

### 已知弱项（不改 prompt 也能接受）

1. **越界/冲突类**偶尔被判为不值得记（它既不是承诺也不是重大生活事件）；
2. **稳定偏好/身体限制**（不吃辣一吃胃疼）在事实层本来就该记，锚点记不记都行，
   金标里算"该记"是为了让模型倾向保留，但漏了也不影响 `/fact` 的事实层；
3. kind 不稳定（shared_experience ↔ secret 偶发互换）。

### 结论

锚点复筛的**误建率是 0（四次跑）**，达到"宁漏不错"的产品取向；召回波动属于可接受范围，
后续若真实数据里出现明显漏记，再针对性调 prompt（金标集就是回归护栏）。
