# 真实验证台：mock OneBot + 真实 DeepSeek 多轮长跑

> 目的：在没有第二台手机/第二个 QQ 号的情况下，用「本地 mock NapCat + 真实模型 + 临时数据目录」把
> QQ 桥接的完整链路跑起来，用**另一个真实 DeepSeek 调用扮演用户**，把对话跑成多轮，再看指标和对话原文找「不像真人」的地方。
>
> **注意**：用户是模型模拟的（25 岁上海男生「阿哲」），不是真人；NapCat 是脚本 mock 的；但 **bridge 进程与 DeepSeek 调用都是真的**。

## 1. 怎么跑

```bash
cd /Users/.../karen-persona
export PATH="$PWD/.runtime/node22/bin:$PATH"

# 15 轮日常场景（真实模型，成本约 ¥0.2-0.5）
.runtime/node22/bin/node node_modules/tsx/dist/cli.mjs scripts/mock-onebot-longrun.ts \
  --scenario daily --turns 15 --gap-ms 12000 --budget-cny 0.5 --voice

# 小规模冒烟（2 轮，约 1-2 分钟）
.runtime/node22/bin/node node_modules/tsx/dist/cli.mjs scripts/mock-onebot-longrun.ts \
  --scenario daily --turns 2 --budget-cny 0.2 --voice
```

## 3. 15 轮基线（2026-10-20）：真实对话里的问题

15 轮全部跑完（session 30 条消息，记忆探针「我下周要去哪出差」→「杭州……你刚自己说的 这才几句话」通过，结束时亲密度 3.09）；本次收尾阶段进程挂起、报告未自动落盘，下列结论来自临时目录里的会话数据。

### 3.1 做得好的地方

- **事实记忆在线**：第 2 轮说的「猫叫年糕」、第 7 轮说的「下周三去杭州出差」，在之后的追问里都答对了，还会自然地吐槽「你刚自己说的 这才几句话」。
- **人设一致**：咖啡店店员的口吻、店里「美式少冰」的日常、猫叫「五花」，都在回复里自然出现。
- **情绪反应**：用户说「代码改了八遍」时她回「八遍……」，用户说「有点丧别嫌我烦」时回「烦啥 我这不一直在回你」——简短、有反应、不解释。

### 3.2 发现的「不像真人」

| # | 问题 | 证据（15 轮原文摘录） | 处理 |
|---|---|---|---|
| 1 | **一轮气泡过多** | 平均 5 条/轮；`MAX_BURST` 原为 15，模型给几行就发几条，再叠照片/语音像刷屏 | `MAX_BURST` 15 → **4**（与 persona「碎短句 2-4 条」一致），超出内容合并进最后一条不丢失。**复跑后：文字气泡 3.27 条/轮，无 5+ 文字气泡轮（§6）** |
| 2 | **用户点名要照片，她只嘴上接话** | 用户连续 3 次：「你店里傍晚啥样，有空拍张给我看看呗」→「等我哪天值班到傍晚」；「你那边现在啥样，拍张照片看看」→「就是一堆杯子跟咖啡机 有啥好看的」；全程 **0 张照片** | 新增 `impulse/media-request.ts`：点名要照片时**跳过概率判定**（亲密度/冷却仍生效）；并给模型内部提示「方便就现在拍，别推说改天」。**复跑后：3/3 次点名媒体都有出站媒体（照片/贴纸），但内容与请求/配文错位，见 §6.3** |
| 3 | **点名要表情包/语音也没有兑现机制** | 「发个表情包给我看看」→「我这表情包都是猫的 你要看吗」（没发）；贴纸/语音都是「回复后低概率顺手发」，与用户请求无关 | 桥接新增「点名要」通道：表情包/语音请求时提高概率并跳过冷却；语音请求时也不吃免打扰/冷却。**复跑后：表情包请求 ✓；语音请求 1/1 未兑现（实际回了照片，文本却称「语音给你发了」），见 §6.3** |
| 4 | **同一轮叠加多种媒体** | 冒烟里出现「照片 + 语音」同轮 | 已发照片/贴纸的轮次不再补语音。**复跑后：6 次语音轮均未与照片/贴纸同轮 ✓** |
| 5 | **打字节奏不像人** | 气泡间隔固定 200–800ms，一条 10 字的消息 0.4s 就发完 | 改为按字数估算（约 80–120ms/字，封顶 3s），首条前 0.3–0.8s「看到消息」 |
| 6 | **口头禅复读** | 15 轮里「笑死」出现 4 次 | 纳入套话句式提醒（最近 3 条同句式 ≥2 次就提示换说法）。**复跑后：套话句式命中 1 次；但同一张熊图 +「刷到一只熊」连续两轮复用，见 §6.3** |
| 7 | **会话里的气泡边界丢失** | 流式回复写库时多条气泡被直接拼成一行（「嗯呐程序员啊张江离我们店还挺远的吧…」），影响后续风格参考与检索 | `sentReply` 改为按 `\n` 保留分条 |

## 4. 复跑与对比

修复后重跑同一场景，应观察：

- 单轮气泡数 ≤ 4（不再出现 5 条）
- 用户说「拍张照片看看」→ 大概率本轮就收到照片（受亲密度/冷却约束）
- 说「发个表情包」「发条语音听听」→ 会有对应消息

## 5. 已知限制

- 用户是模型模拟的，语义多样性不如真人；它也会有「机器人式」的提问节奏。
- mock NapCat 只覆盖 OneBot 11 的协议形态（send/delete/echo），**不覆盖真实 QQ 的语音条转码、风控、图片 URL 私有化**。
- 15 轮基线暴露了 harness 收尾阶段的挂起问题（LLM 评审/进程退出缺超时），已在 `scripts/mock-onebot-longrun.ts` 收尾处加超时与强制退出；复跑时若再遇到挂起，用 `--turns 6` 小规模验证收尾。**2026-10-20 复跑验证：15 轮 / 540s 正常退出，报告在评审前后各落盘一次（评审挂起也不会丢数据）。**
- 语音只在 macOS 上真正合成（`say`），其它平台该维度为 0。

### 6.2 修复验证结论

- ✅ 单轮文字气泡 ≤4；✅ 点名照片/表情包有出站媒体；✅ 同轮不同时出现照片+语音；✅ 打字节奏带来 p50 3.2s（符合预期）；✅ 收尾不再挂起。

- ❌ 编造相识场景仍在（最严重）：第 13 轮编出「每周来三四次 / 下雨借伞」，LLM 评审记忆一致性给 2 分。

### 6.3 复跑暴露的新问题与建议

1. **编造「怎么认识的」具体场景（P0，最伤真人感）**：第 13 轮「你每周来三四次 坐吧台 / 有次下雨没带伞 / 我借你的 / 后来就熟了呗」——用户此前从未说过线下见过面，与「程序员、刚在网上聊」矛盾。建议：`relationship_background` 为空且无首次见面事实时，prompt 强制「你们还没在线下见过 / 别编具体场景」，并在输出后做确定性拦截（与反「我记性没那么差」同族的 reply-guard）。
2. **多媒体内容与请求/配文错位（P0）**：要晚霞发了花/山、要语音只发照片且文本称「语音给你发了…远处的山和云」；本地兜底图库配文仍用「今天/昨天」口吻。建议：媒体请求要参与选图与配文（请求→photo query/caption 绑定）；本地兜底图只用模糊时间口吻（「翻到一张」），不要声称「刚拍」；语音请求未发出时不要让模型说「发了」。
3. **情绪承接被抢话题（P1）**：第 2/3 轮用户吐槽老板，她连续两轮「刷到一只熊」；第 12 轮用户说丧，她转去讲店里客人「非说咖啡太酸」。建议：检测用户负面情绪时先共情/追问 1 句，再输出自身内容（prompt 或后处理约束）。
4. **记忆防御话术偏嘲讽（P2）**：「才说的就忘啦」「你自己刚说的 才两句就忘啦」——事实记忆 3/3 但语气减分。建议：reply-guard 覆盖该族（「记性没那么差」「才说的就忘啦」「才两句」），改成更轻的「刚说过呀」。
5. **同一媒体/配文跨轮复用（P2）**：第 2/3 轮同一张熊图 +「刷到一只熊」两连。注意本次验证配置把 photo cooldown 设为 0（为观察链路），生产默认 2h 冷却会缓解；仍建议按 photo id + caption 做近 N 轮媒体去重。
6. **配置提示**：本次为「看清链路」把 `voice_probability` 调到 0.6、`photo_share_probability` 0.3、冷却 0；产品默认是 0.12 / 2h，**不能把本次照片/语音频率直接当产品质量指标**。

## 7. 第二轮验证：修复后又打脸，以及真正的根因（2026-10-20）

### 7.1 第二轮 15 轮（v0.3.1 修复前，¥0.1220）

| 指标 | 数值 |
|---|---|
| 回合 / 有回复 / no_reply | 15 / 15 / 0 |
| 首条延迟 | p50 3.2s、p95 6.3s |
| 文字气泡 | 3.27 条/轮（修复前是 5） |
| 多媒体 | 照片 9、贴纸 2、语音 4；同轮照片+语音 0 |
| 记忆探针 / 复读对 / 红线 | 3/3 / 0 / 0 |
| LLM 评审 | 真人感 3 / 连贯 3 / 主动 3 / **多媒体 2** / **记忆 2** |

评审仍然点名了两个问题：

1. **第 13 轮问「我们俩是怎么认识的」，她答「就店里的常客呗 / 你老来喝咖啡 / 有天雨没带伞，我把备用伞借你了」**——即使这一版已经加了 prompt 禁令和确定性守卫。
2. **照片配文高度重复、和上下文无关**（爬山、湖边、花反复出现，像随机贴图）。
3. 用户说「有点丧」时她只回「那早点睡」，缺共情与追问。

### 7.2 根因：人设自带的「相遇故事」被当成了既定事实

查 `personas/xiaoya/persona.json` 发现 `relationship.howWeMet` 里本来就写着：

> 「你是咖啡店的常客，每周来三四次……有一次下雨你没带伞，她把店里的备用伞借给你……」

而 `prompt-builder` 会把这句原样注入 system prompt，`meeting-guard` 的「有依据」判断也把它算成依据——于是模型只是**照着人设背**，守卫还认为「有依据，放行」。

对用户来说，他从没来过这家店，这就是编造。

### 7.3 修复

- **不再把人设故事当事实**：`buildMeetingBackground()` 只认用户自己写的 `relationship_background`；人设里的 howWeMet 若含具体细节（伞/下雨/每周来几次/吧台…）一律降级为「在咖啡店认识的，但具体怎么熟起来记忆里没有明确记录（不要编造细节）」。
- **守卫只认用户侧证据**：`hasMeetingGrounding` 不再接受人设 howWeMet，只看用户背景 / 用户事实 / T2 记忆。
- **照片配文去重**：每个用户记住最近 5 条配文、最近 3 张图，选图选句时优先排除。
- **强场景词也参与选图**：普通聊天里提到晚霞/雪/咖啡/猫/山/湖时，即使没点名要照片，也优先挑对应场景的图。
- **「发张你那边晚霞看看」这类没有「照片/图」字样的请求**也识别为要照片（补 `发张/拍张/来张` 模式）。
- **首条消息就是「我成年了」不再被年龄门提示吞掉**（桥接层修复）。

### 7.4 修复后定向验证（5 轮真实模型，¥0.02）

| 用例 | 修复前 | 修复后 |
|---|---|---|
| 「我们俩是怎么认识的来着？」 | 每周来三四次 / 坐吧台 / 下雨借伞 | 「嗯？」「你认真的吗」「在店里认识的啊」——**没有具体细节** ✅ |
| 「发张你那边晚霞看看呗」 | 只嘴上接话 / 发不对场景 | 文字 + **晚霞/湖边照片**，配文「昨天在湖边站了一会儿」 ✅ |
| 「今天真有点丧，项目又出 bug 了」 | 「那早点睡」 | 「又出 bug 啦 / 是那种改了半天发现改错地方的吗」——先接情绪再追问 ✅ |

### 7.5 仍然存在的问题

- 评审的「多媒体」分数仍受验证配置影响（验证台把 photo_probability 调到 0.25、冷却 0 才方便看清链路，生产默认约 0.08 + 冷却 2h，频率低很多）；配文多样性是弱项（当时 7 张图 × 3 种时间关系），已在 **v0.3.2** 扩到 15 张图 / 约 110 条配文并加去重，等下一轮 15 轮复验再看评审分数是否回升。
- 情绪承接靠 prompt 规则 + 模型自觉，没有确定性保障；偶发仍会偏敷衍。
- 「在店里认识的」这句仍然来自人设的安全兜底描述——如果用户希望完全不知道，需要把人设的 howWeMet 也改掉或置空。

### 8.1 仍存在的问题（评审点名的）

- **主动开启话题偏少**：多数轮次顺着问话回应，很少主动带自己的近况（评审 主动 3/5）。
- **共情略浅**：被吐槽加班/挨批时接得住但不够深（真人感 4/5 的主要扣分项）。
- **部分回复偏短**：受 persona「碎短句 2-4 条」约束，个别轮次缺追问或延伸，推进感弱。

这三项都属于「模型行为 + prompt 调优」，且与 persona 设定（不以问句结尾、碎短句）存在张力，后续若要动，需要小步 A/B，不能直接加「多问问题」这类规则。

## 9. 说话动作 A/B 与气泡治理（2026-10-20，v0.3.3）

### 9.1 改造内容

针对上一轮评审的三点（主动开话题偏少 / 共情略浅 / 回复偏短），加了一个「说话动作」选择器
（`src/persona/talk-moves.ts`）：对方在倒苦水时给模型一句内部提示「先接住情绪、别马上转到自己」；
否则以 28% 概率提示「顺手补一句自己的近况」。带亲密度门槛、连续两轮不重复、危机/免打扰不触发，
`KAREN_TALK_MOVES=off` 可整体关闭。

### 9.2 A/B：没测出收益

同一天、同一场景（daily 前 8 轮，gap 7s，语音开），只切 `KAREN_TALK_MOVES`：

| 指标 | off | on |
|---|---|---|
| LLM 评审 真人感 / 连贯 / 主动 / 多媒体 / 记忆 | **4 / 3 / 3 / 2 / 4** | **3 / 3 / 3 / 2 / 4** |
| 照片 / 贴纸 / 表情 / 语音 | 4 / 2 / 3 / 3 | 7 / 2 / 0 / 0 |
| 首条延迟 p50 / p95 | 3.3s / 5.2s | 3.6s / 6.4s |
| 成本 | ¥0.0483 | ¥0.0505 |

结论：**8 轮样本 + 单次评审的噪声，大于这条提示可能带来的差异**；开的那组照片反而更多（是随机概率，
不是这条提示造成的）。所以这一版**没有证据表明「说话动作」提示提升了质量**，只能说它没有明显副作用。

### 9.3 但 A/B 暴露了三个真问题（已修）

1. **单轮气泡过多**：出现过一轮 6–9 条（流式路径不受 `MAX_BURST` 约束）。→ 桥接限制**每轮最多 4 条文字气泡**，超出内容合并成一条。
2. **当轮自我重复**：「被说啦 / 气人 / 被说啦？」同一轮里说两遍。→ 出站前按 `detectRepetition` 做**当轮去重**。
3. **情绪轮发无关照片**：对方在倒苦水，她顺手发窗台/杯子照。→ **糟心事轮次不触发非点名的主动发图**（点名要图仍发）。

另外顺手修了贴纸跨轮复用（最近 3 张不重复）。

### 9.4 修复后 8 轮（照片概率改用生产值 0.08，¥0.0490）

| 指标 | A/B 时（0.3/冷却 0） | 修复后（0.08） |
|---|---|---|
| 单轮文字气泡 | 6–9 | **4–5** |
| 照片 / 贴纸 / 表情 / 语音 | 7 / 2 / 0 / 0 | **2 / 2 / 1 / 3** |
| 评审 真人感 / 连贯 / 主动 / 多媒体 / 记忆 | 3 / 3 / 3 / 2 / 4 | **4 / 4 / 3 / 4 / 4** |
| p50 / p95 延迟 | 3.6s / 6.4s | 3.3s / 3.5s |

### 9.5 评审剩下的问题，以及一个「假重复」

- **主动仍 3/5**：多数回合还是回应式；这条提示没有解决，需要更结构化的做法（例如「冷场主动抛话题」链路，
  qq-agent-plus 的做法是三条独立链路 + 跳过原因日志，见 docs/RESEARCH_REFERENCE.md）。
- **部分回复偏短**（「啊……」「嗯呐」）：与 persona「碎短句」设定冲突，暂不动。
- **「笑死，踩脸也太狠了呢 / 笑死，踩脸也太狠了」被判重复**：查了去重函数，这两句相似度 0.875 ≥ 阈值、
  函数返回 `duplicate=true`；真实原因是**打错字撤回 + 重发**，而 mock 之前只记录 `send_private_msg`、
  不记录 `delete_msg`，评审看到的就成了「同一句发两遍」。已在 mock 里记录撤回，transcript 渲染为
  「〔她撤回了一条消息〕」，后续评审不会再误判。

### 9.6 验证配置提醒

验证台默认 `photo_share_probability: 0.3`、冷却 0（为了看清照片链路），生产默认约 0.08 + 2 小时冷却。
**别拿验证台的照片频率当产品质量指标**；本轮起验证默认用 0.08。
