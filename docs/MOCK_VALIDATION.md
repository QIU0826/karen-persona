# 真实验证台：mock OneBot + 真实 DeepSeek 多轮长跑

> 目的：在没有第二台手机/第二个 QQ 号的情况下，用「本地 mock NapCat + 真实模型 + 临时数据目录」把
> QQ 桥接的完整链路跑起来，用**另一个真实 DeepSeek 调用扮演用户**，把对话跑成多轮，再看指标和对话原文找「不像真人」的地方。
>
> **注意**：用户是模型模拟的（25 岁上海男生「阿哲」），不是真人；NapCat 是脚本 mock 的；但 **bridge 进程与 DeepSeek 调用都是真的**。

## 1. 怎么跑

```bash
cd /Users/.../karen-persona
export PATH="$PWD/.runtime/node22/bin:$PATH"

# 15 轮日常场景（真实模型，成本约 ¥0.2-0.5）
.runtime/node22/bin/node node_modules/tsx/dist/cli.mjs scripts/mock-onebot-longrun.ts \
  --scenario daily --turns 15 --gap-ms 12000 --budget-cny 0.5 --voice

# 小规模冒烟（2 轮，约 1-2 分钟）
.runtime/node22/bin/node node_modules/tsx/dist/cli.mjs scripts/mock-onebot-longrun.ts \
  --scenario daily --turns 2 --budget-cny 0.2 --voice
```

隔离红线（脚本内断言）：

| 项 | 取值 |
|---|---|
| 工作目录 / 数据目录 | `os.tmpdir()/karen-mock-longrun-*`（`KAREN_DATA_DIR` 指向临时目录，跑完删除） |
| OneBot WS | `ws://127.0.0.1:19180/onebot/v11/ws` |
| health / cost | `http://127.0.0.1:19181`（`web_port: 0` 关闭控制台） |
| 真实端口 | **禁止使用 18080 / 18081 / 18082**（那是真人正在用的桥接） |
| 真实 `data/` | 不读写 |

## 3. 15 轮基线（2026-10-20）：真实对话里的问题

15 轮全部跑完（session 30 条消息，记忆探针「我下周要去哪出差」→「杭州……你刚自己说的 这才几句话」通过，结束时亲密度 3.09）；本次收尾阶段进程挂起、报告未自动落盘，下列结论来自临时目录里的会话数据。

### 3.1 做得好的地方

- **事实记忆在线**：第 2 轮说的「猫叫年糕」、第 7 轮说的「下周三去杭州出差」，在之后的追问里都答对了，还会自然地吐槽「你刚自己说的 这才几句话」。
- **人设一致**：咖啡店店员的口吻、店里「美式少冰」的日常、猫叫「五花」，都在回复里自然出现。
- **情绪反应**：用户说「代码改了八遍」时她回「八遍……」，用户说「有点丧别嫌我烦」时回「烦啥 我这不一直在回你」——简短、有反应、不解释。

### 3.2 发现的「不像真人」

| # | 问题 | 证据（15 轮原文摘录） | 处理 |
|---|---|---|---|
| 1 | **一轮气泡过多** | 平均 5 条/轮；`MAX_BURST` 原为 15，模型给几行就发几条，再叠照片/语音像刷屏 | `MAX_BURST` 15 → **4**（与 persona「碎短句 2-4 条」一致），超出内容合并进最后一条不丢失 |
| 2 | **用户点名要照片，她只嘴上接话** | 用户连续 3 次：「你店里傍晚啥样，有空拍张给我看看呗」→「等我哪天值班到傍晚」；「你那边现在啥样，拍张照片看看」→「就是一堆杯子跟咖啡机 有啥好看的」；全程 **0 张照片** | 新增 `impulse/media-request.ts`：点名要照片时**跳过概率判定**（亲密度/冷却仍生效）；并给模型内部提示「方便就现在拍，别推说改天」 |
| 3 | **点名要表情包/语音也没有兑现机制** | 「发个表情包给我看看」→「我这表情包都是猫的 你要看吗」（没发）；贴纸/语音都是「回复后低概率顺手发」，与用户请求无关 | 桥接新增「点名要」通道：表情包/语音请求时提高概率并跳过冷却；语音请求时也不吃免打扰/冷却 |
| 4 | **同一轮叠加多种媒体** | 冒烟里出现「照片 + 语音」同轮 | 已发照片/贴纸的轮次不再补语音 |
| 5 | **打字节奏不像人** | 气泡间隔固定 200–800ms，一条 10 字的消息 0.4s 就发完 | 改为按字数估算（约 80–120ms/字，封顶 3s），首条前 0.3–0.8s「看到消息」 |
| 6 | **口头禅复读** | 15 轮里「笑死」出现 4 次 | 纳入套话句式提醒（最近 3 条同句式 ≥2 次就提示换说法） |
| 7 | **会话里的气泡边界丢失** | 流式回复写库时多条气泡被直接拼成一行（「嗯呐程序员啊张江离我们店还挺远的吧…」），影响后续风格参考与检索 | `sentReply` 改为按 `\n` 保留分条 |

## 4. 复跑与对比

修复后重跑同一场景，应观察：

- 单轮气泡数 ≤ 4（不再出现 5 条）
- 用户说「拍张照片看看」→ 大概率本轮就收到照片（受亲密度/冷却约束）
- 说「发个表情包」「发条语音听听」→ 会有对应消息
- 同轮不同时出现 照片+语音
- 首条延迟会因打字节奏略升（约 +0.3–1.5s），属于预期

## 5. 已知限制

- 用户是模型模拟的，语义多样性不如真人；它也会有「机器人式」的提问节奏。
- mock NapCat 只覆盖 OneBot 11 的协议形态（send/delete/echo），**不覆盖真实 QQ 的语音条转码、风控、图片 URL 私有化**。
- 15 轮基线暴露了 harness 收尾阶段的挂起问题（LLM 评审/进程退出缺超时），已在 `scripts/mock-onebot-longrun.ts` 收尾处加超时与强制退出；复跑时若再遇到挂起，用 `--turns 6` 小规模验证收尾。
- 语音只在 macOS 上真正合成（`say`），其它平台该维度为 0。
