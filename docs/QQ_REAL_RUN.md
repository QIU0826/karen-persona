# 真实 QQ 长跑验证

> 目的：验证「真实 QQ 用户 ↔ NapCat ↔ 桥接 ↔ DeepSeek」整条链路，而不只是 mock E2E。
> 原则：所有结论都来自**真实消息 + 本地日志/数据库**；没有样本就写「未验证」，不编。

## 1. 前置

- 桥接已启动（`npm run qq`），NapCat 已连接（`/health` 里 `ws_connections ≥ 1`）；
- 用白名单里的 QQ 号给 Karen 的 QQ 发消息；
- 如果是新用户：第一条消息会收到「AI 披露 + 18 岁确认」，回复「我成年了」后进入正常对话。

## 2. 观察工具（只读）

跑长跑观察（默认 1 小时，可调）：

```bash
npm run qq:watch -- --duration 1800 --interval 5
```

- 只读打开 `data/memory.sqlite`，不影响桥接；
- 实时打印新回合（用户 → 她，含延迟）、成本、事实数；
- 结束时在 `data/` 写 `realrun-<时间>.json` 与 `.md` 报告（含对话原文，600 权限，注意隐私）；
- Ctrl-C 也会先落报告。

报告包含：回合数、空回复/重复回复、平均/P95 延迟、成本（按用途）、事实数、同意记录、异常标记。

## 3. 首轮真机结果（2026-10-20 13:51–13:54，本机）

| 时间（本地） | 事件 | 结果 |
|---|---|---|
| 13:51:04 | 用户首条消息（老会话已有 100 条历史） | 收到年龄门确认请求 |
| 13:51:15 | 回复「我成年了」 | 记录 18+ 确认，进入对话 |
| 13:51:22 | 「你在干嘛」 | 3.8s 后回复「刚歇下来 喝口水下午还有一波人」 |
| 13:51:40 | 「啥呀？忘记你是干什么的了」 | **被门控延迟 31 分钟**（bug，见下） |
| 13:54:06 | 用户追问「哈喽？怎么不鸟我呢」 | 取消延迟，3s 后回复「卖咖啡的呀 才一个小时就忘」 |

真实成本：这几轮主对话 + 旁路调用合计约 **¥0.0057**（`/cost` 可复现）。

### 首轮暴露并修复的问题

1. **老用户没有收到 AI 披露**（合规风险）
   - 原因：披露是否发送只看「会话文件是否为空」；升级用户已有上百条历史，被跳过。
   - 修复：`shouldSendDisclosure({enabled, acknowledgedAt})` 按 `user_consent.disclosure_acked_at` 判断，按 owner 只补发一次；
     同时披露/`/about` 文案不再硬编码「小雅」，改用当前人设名（多设用户不会说错人）。
2. **快速追问被误判为普通消息，随机延迟 31 分钟**
   - 原因：消息门在写入当前用户消息之前计算「5 分钟内连续发 ≥2 条」，当前这条没有计入，
     18 秒后的第二句被判成普通消息，掷中了工作时段延迟。
   - 修复：`buildGateContext` 把当前消息的时间戳计入连续跟进判断（`messageCountToday` 语义不变），
     补回归测试「刚回完一句紧跟的第二句算连续跟进」。
3. **长跑观测缺工具**
   - 新增 `src/eval/qq-realrun.ts` + `scripts/qq-longrun-watch.ts`（`npm run qq:watch`）+ 单测。

修复后桥接已重启；后续真实对话继续用 `qq:watch` 观察。**目前样本仅 3 轮，不构成「长期稳定」结论。**
