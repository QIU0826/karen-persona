## 核心技术方案

### 1. 六层人格引擎 —— 结构化人设表达与动态合成

**问题**：传统 ChatBot 将人设写成一段自然语言 Prompt（"你是一个温柔的女孩..."），LLM 对长 Prompt 的遵循度随对话增长快速衰减，20+ 轮后崩塌率显著上升。

**方案**：将人格拆分为 6 个独立层，每层有独立的 TypeScript 类型定义和演化逻辑。Prompt 构建时将 6 层编译为 ~15 token 的结构化状态标签（非自然语言注入），状态值通过 EMA 平滑（α=0.3）防止单轮跳变。

```
L1: 弹性硬规则层 → resistance 系数 (0-1) + 链式裁决 (触发→内心→行为)
L2: 身份层 → 姓名/年龄/职业/所在地/MBTI/星座
L3: 风格层 → 正式度/温暖度/直接度/幽默度/惯用语
L4: 情绪层 → 基线效价 + 波动性 + 恢复速率 + 依恋类型 (安全/焦虑/回避/混乱)
L5: 关系层 → 亲密度 (1-10) + 共享语境 + 边界
L6: 世界层 → 职业/爱好/社交圈/日常节律/人生哲学
```

**关键设计**：L1 规则不是"禁止 X"的 Prompt 指令，而是 `trigger → internal → behavior` 三阶段链式结构。每条规则带 0-1 resistance 系数，突破后产生 guilt（愧疚负债），负债通过三种外交结局（接受/拒绝/未被注意）偿还。这避免了传统 Prompt 禁令的死板——她可以打破规则，但需要付出心理代价。

**实测数据**：
- 括号使用率：秋瑶 (安全型) 0.0%，小雅 (回避型) 13.0%（设计预期内——回避型需更高 resistance 约束，已反馈调优）
- 问句结尾率：2.0%（目标 < 5%）
- AI 身份暴露：0 次 / 197 回复
- 碎片化指数：1.0（197 条回复全部呈 5-50 字碎片化短句风格）

### 2. T0-T3 四级记忆代谢系统 —— 带生命周期的记忆管理

**问题**：长对话场景下，RAG 用原始对话片段检索会出现语义漂移（"她上次说的是什么事来着？"）和幻觉传播（错误记忆被反复检索强化）。

**方案**：四级记忆，每级有不同的存储粒度、衰减策略和晋升规则。

| 级别 | 粒度 | 存储 | 衰减策略 | 晋升条件 |
|------|------|------|---------|---------|
| T0 | 原始对话消息 | 内存滑动窗口 (200 条) | FIFO | — |
| T1 | 每轮对话快照 (情绪/亲密度/愧疚度) | SQLite 行 | 无衰减 (全量保留) | 每次对话后写入 |
| T2 | 情节记忆 (768 维向量) | sqlite-vec | 艾宾浩斯指数衰减，情绪加权半衰期 | T0 对话自动提取 |
| T3 | 长期摘要 (LLM 叙事化压缩) | SQLite 行 | 90 天半衰期 | 每 80 条 T2 触发 LLM 压缩 |

**关键设计**：
- T2 检索不依赖原始对话片段。每条记忆独立衰减、独立检索，避免语义漂移。
- 情绪加权半衰期：高唤醒度记忆衰减更慢（基于忆级效应理论），T2 平均强度 0.427（198 条记忆自然衰减中）。
- T3 摘要器：LLM 将 80 条 T2 压缩为 3-5 句叙事，原始条目强度降至 30%，避免重复检索。
- 检索公式：`relevance = cosineSimilarity × decayedStrength × (1 + |emotional_weight|)`
- CategoryRAG：按 6 个认知域（传记/经历/偏好/社交圈/工作/心理特征）独立建索引，按域检索，单次检索延迟 8ms（173 条 T2，n-gram FNV-1a，单机 better-sqlite3 实测）。

**实测数据**：
- T1: 130 条，T2: 198 条（91 条已自然衰减至 strength < 0.3），T3: 4 条
- 嵌入覆盖率：87.9%（174/198）
- n-gram FNV-1a 自检索 Recall@1：**99.4%**（173 条已嵌入记忆查自身，172 条排第一）
- 内心独白日志：72 条（fire-and-forget 异步写入）
- 人设进化日记：1 篇（月度 LLM 叙事化生成）

### 3. 主动行为决策系统 —— 从被动回放到主动交互

**问题**：传统 ChatBot 完全被动——用户不发消息，系统永远沉默。

**方案**：三层行为决策架构。

**消息门控 (Message Gate V2)**：每次收到消息时计算是否回复。5 种决策——回复 / 延迟 / 沉默-回避 / 沉默-愧疚驱动 / 遗忘。决策因子：时间、情绪向量、愧疚度、亲密度、消息类型（文字/图片/语音）、是否为回避话题、是否为自然收尾。3 种豁免规则：当日前 3 条消息 / 30s 内快速跟进 / 3 轮内快聊。

**静默状态机**：追踪用户最后活跃时间，4 阶段（6h / 24h / 72h / 72h+）。阶段 4 触发重启消息，发送后进入冷却。

**主动心跳 (Proactive Heartbeat)**：每 15 分钟扫描 4 类触发源——因果链进展 / 天气变化 / 情绪波动 / 时间节点。按优先级排序（因果链 > 天气 > 情绪 > 时间），触发概率与优先级成正比。深夜冲动被消息门延迟但产生内心独白日志（已积累 72 条）。

**消息门控消融实验**：在 38 个参数化测试场景上扫描 3 个豁免参数。默认配置（前 3 条豁免 / 30s 窗口 / 3 轮快聊）下回复率 63.2%、延迟率 34.2%、沉默率 2.6%。灵敏度最高的是快聊豁免轮数（回复率波动 21 个百分点），最低的是每日豁免条数（10.5 个百分点）。三个参数的推荐范围均覆盖默认值，验证了默认配置的合理性。

### 4. 动态人格演化 —— Persona 不是静态配置

EMA 平滑的情绪基线更新（α=0.3）。4 阶段心理状态追踪（无觉察→注意到→否认→承认），按依恋类型差异化进展速度。月度 LLM 叙事化生成"这段时间的你"，写入 T2 作为长期自我认知。

## 工程实现

### 代码规模与质量
- 10 个独立域，~70 个源文件，TypeScript 编译零错误
- 178 测试用例，11 测试文件
- 人格引擎模块（prompt-builder/emotion/guilt-repayment）417+135+154 = 706 行测试，覆盖率 > 80%
- 关系弧线 / 情感分析 / 健康检查 3 个评估模块，45 个专项测试

### 性能与稳定性
- 消息复杂度分级：规则驱动零延迟（≤80 / ≤250 / >250 字 → simple/normal/complex → flash/pro 路由）
- 流式响应：AsyncGenerator 逐 token 输出，自然断句（`。！？…` 立即发送，逗号 12 字+ 发送），中断检测（新消息到达 → 标记 interrupted → 下轮 prompt 注入情境信号）
- 400ms 消息合并窗口：连续消息合为一批处理，模拟"看到两条一起回"
- LLM 重试 2 次 + >5s 慢响应日志

### 消息接入
- QQ 桥接：NapCatQQ + OneBot 11，WebSocket 反向连接（本服务作为 WS Server）
- 支持私聊（流式响应 + 中断检测 + 图片识别 + Unsplash 主动发图）和群聊（@ 触发 + 仅回复认识的人）
- 频率限制、用户状态 LRU 淘汰（500 上限）、连接断线通知

### 部署
- PM2 进程守护，`ecosystem.config.js` 配置
- Dockerfile（开发者贡献用）
- Setup Wizard 交互式初始化

## 待完善与局限性

1. **缺乏 LLM-as-Judge 自动化评测**：已建立 6 维规则指标评分卡（括号率/问句率/长度适中/碎片化/非重复/身份保护），综合得分 93/100（197 条回复实测）。但未引入 LLM-as-Judge 对内容质量（身份一致性、情绪真实性）做主观评分——评测框架已搭建（`consistency-eval.ts` 含 Judge prompt 模板和评分维度），待接入 LLM API 后执行。
2. **A/B 对照未跑 LLM**：已搭建纯 Prompt 基线生成器（`buildBaselinePrompt`），可一键生成与结构化引擎对比的基线 system prompt。但受限于 LLM API 调用成本，尚未实际让基线方案跑完 197 条回复并做同输入对比——对比框架和评分逻辑已完成（`compareAB` + `formatABReport`）。
3. **用户规模为零**：只有开发者本人测试数据（2 个会话、197 条回复），缺乏真实多用户、长周期运行数据（留存率、对话轮次分布等）。
4. **嵌入回退已量化**：n-gram FNV-1a 自检索 Recall@1 = **99.4%**, Recall@5 = 100%（173 条记忆实测）。相比 Qwen embedding 的检索质量差距需在配置 API key 后测量——对比框架已搭建（`embedding-bench.ts`）。
5. **消息门控已做消融实验**：3 参数 × 17 组合在 38 个参数化测试场景上扫描完成，默认配置均在推荐范围内，验证了经验设定的合理性。
