# 离线行为评测（v0.9.8）

## 1. 为什么需要

v0.9.5 与 v0.9.7 两次 mock 长跑 A/B 都只有「单次 6 轮」：
LLM 评审 ±1 波动，自述率 2/6 vs 3/6 完全在噪声内——**无法判断改动有没有效**。
继续用单次长跑下结论，只会得到"看起来有变化"的随机结果。

## 2. 做法

```
固定 12 条用户消息 × N 个种子 × 变体
  → 用**生产 system prompt**（persona/prompt-builder.buildPrompt）
  → 逐轮真实模型调用（温度 0.95，保留多轮历史）
  → 每轮记录：是否自述她自己的生活、字数、是否问句、重复对、开头复读对
  → 聚合为「均值（最小–最大）」，比较变体的范围是否重叠
```

- 命令：`npm run behavior:eval`（默认 2 变体 × 3 种子 × 12 条 ≈ ¥0.065，约 2 分钟）
- 变体通过提示注入实现（如 v0.9.7 的自述提及预算），**不改生产代码路径**
- 指标模块：`src/eval/behavior-metrics.ts`（纯函数 + 12 条单测）
- 注意：这是**离线提示级评测**，不是真实 QQ 对话；范围大幅重叠时不能宣称有效。

## 3. 用它回测 v0.9.7「自述提及预算」

| 指标 | 基线（无预算） | 提及预算（v0.9.7） |
|---|---|---|
| 自述提及率 | **39%（33%–50%）** | **47%（42%–50%）** |
| 平均字数 | 18.2（12.9–27.1） | 18.5（13.6–22.1） |
| 问句率 | 17%（8%–25%） | 25%（17%–33%） |
| 完全重复对 | 0 | 0 |

**结论**：区间大幅重叠，均值方向甚至相反（+8pp）→ **未测出收益**。
结合 mock 长跑的同向结果，v0.9.8 把 pacing **默认关闭**，保留检测与指标。
这就是这个框架的价值：**避免把随机波动当成改进发布出去**。

## 4. 局限

- 用户消息是固定脚本，不是真人；只覆盖 12 条、一个场景。
- 温度 0.95 下同一变体内部波动本来就大（基线字数 12.9–27.1），
  所以只适合判断"大效应"（比如 >15pp），不适合判断 5pp 级差异。
- 变体通过提示注入近似，若改动涉及程序逻辑（不是 prompt）仍需真实长跑验证。
- 成本随种子线性增长；种子 ≥5 时结论更稳（约 ¥0.11）。
