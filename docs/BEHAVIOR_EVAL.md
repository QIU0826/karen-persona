# 离线行为评测（v0.9.8）

## 1. 为什么需要

v0.9.5 与 v0.9.7 两次 mock 长跑 A/B 都只有「单次 6 轮」：
LLM 评审 ±1 波动，自述率 2/6 vs 3/6 完全在噪声内——**无法判断改动有没有效**。
继续用单次长跑下结论，只会得到"看起来有变化"的随机结果。

## 2. 做法

```
固定 12 条用户消息 × N 个种子 × 变体
  → 用**生产 system prompt**（persona/prompt-builder.buildPrompt）
  → 逐轮真实模型调用（温度 0.95，保留多轮历史）
  → 每轮记录：是否自述她自己的生活、字数、是否问句、重复对、开头复读对
  → 聚合为「均值（最小–最大）」，比较变体的范围是否重叠
```

- 命令：`npm run behavior:eval`（默认 2 变体 × 3 种子 × 12 条 ≈ ¥0.065，约 2 分钟）
- 变体通过提示注入实现（如 v0.9.7 的自述提及预算），**不改生产代码路径**
- 指标模块：`src/eval/behavior-metrics.ts`（纯函数 + 12 条单测）
- 注意：这是**离线提示级评测**，不是真实 QQ 对话；范围大幅重叠时不能宣称有效。

## 3. 用它回测 v0.9.7「自述提及预算」

| 指标 | 基线（无预算） | 提及预算（v0.9.7） |
|---|---|---|
| 自述提及率 | **39%（33%–50%）** | **47%（42%–50%）** |
| 平均字数 | 18.2（12.9–27.1） | 18.5（13.6–22.1） |
| 问句率 | 17%（8%–25%） | 25%（17%–33%） |
| 完全重复对 | 0 | 0 |

**结论**：区间大幅重叠，均值方向甚至相反（+8pp）→ **未测出收益**。
结合 mock 长跑的同向结果，v0.9.8 把 pacing **默认关闭**，保留检测与指标。
这就是这个框架的价值：**避免把随机波动当成改进发布出去**。

## 4. 实验二：反问钩子（v0.9.9，未采纳）

**假设**：评审多次说「几乎不主动反问用户，像单方面应答」。加一个概率触发的
「问一个具体的小问题」提示，也许能让问句率上升、互动更像来回拉扯。

**实现**（`src/persona/question-hook.ts`，10 条单测，**未接入生产**）：
35% 概率触发；最近 2 条回复已有问句 → 冷却；对方在讲糟心事 / 危机轮 / 对方正在提问 → 不触发。

**结果一（3 种子）**：

| 指标 | 基线 | 反问钩子 |
|---|---|---|
| 问句率 | 19%（8–33%） | 25%（17–33%） |
| 平均字数 | 16.8 | 20.6 |
| 自然度（LLM 评审） | 4/5 | 4/5 |

**结果二（5 种子，降低噪声）**：

| 指标 | 基线 | 反问钩子 |
|---|---|---|
| 问句率 | **13%（0–33%）** | **13%（8–17%）** |
| 平均字数 | 17.1 | **23.9** |
| 自述提及率 | 43% | 50% |
| 自然度 / 提问频率感 | 4/5 / 合适 | 4/5 / 合适 |

**结论**：问句率 **+0pp**（5 种子），只是让回复变长；自然度没有提升。
→ **不接入生产**（模块保留在仓库，供以后换更强模型/更多样本再测）。
这也验证了框架的用途：**假设听起来很合理，数据不支持就不上**。

## 5. 实验三：flash vs v4-pro 模型能力对照（v0.9.10）

**假设**：连续三轮提示词小改动都无收益后，也许该换更强的模型（v4-pro）。
用同一套固定消息 × 3 种子分别跑两个模型，看自然度/问句率/自述率是否显著提升。

| 指标（基线变体） | deepseek-flash | deepseek-v4-pro |
|---|---|---|
| 自述提及率 | 42%（33–50%） | 39%（25–50%） |
| 平均字数 | 20.4（14.8–29.3） | 17.6（15.0–22.1） |
| 问句率 | 8%（0–25%） | 14%（8–17%） |
| 完全重复对 | 0 | 0 |
| 自然度（LLM 评审） | **4/5** | **4/5** |
| 成本上限（全 miss，非高峰估算） | ≈¥0.13 | **≈¥0.57（4.5×）** |

**结论**：在 12 条固定消息的离线评测里，**pro 没有测出可辨识的质量提升**
（自然度同为 4/5，其它指标区间重叠），成本却是 4.5 倍。
→ **日常对话继续默认用 flash**；pro 保持现有路由（复杂问题才走），不为普通聊天切换。
这个结论和"提示词加料无效"一起说明：**当前瓶颈更可能在上下文结构与记忆注入方式，而不是模型规模**。

## 6. 局限

- 用户消息是固定脚本，不是真人；只覆盖 12 条、一个场景。
- 温度 0.95 下同一变体内部波动本来就大（基线字数 12.9–27.1），
  所以只适合判断"大效应"（比如 >15pp），不适合判断 5pp 级差异。
- 变体通过提示注入近似，若改动涉及程序逻辑（不是 prompt）仍需真实长跑验证。
- 成本随种子线性增长；种子 ≥5 时结论更稳（约 ¥0.11）。
