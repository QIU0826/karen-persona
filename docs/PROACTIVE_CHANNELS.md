# 主动消息：四条链路与可解释决策（v0.4.0）

> 代码：`src/impulse/proactive-plan.ts`（纯决策，34 条单测）、`src/pipeline/orchestrator.ts`（`processProactive` 接入）、`src/bridge/qq.ts`（心跳调用）
> 模拟脚本：`scripts/proactive-sim.ts`（离线、不调模型，可复现）
> 本文所有数字都来自仓库内可重复运行的命令，不是估计值。

## 1. 为什么改

改之前，「她主动找你」只有两条路：

1. **生活流心跳**：因果链 / 天气 / 情绪 / 时间节点里挑一个高优先级的，掷一次概率，过消息门；
2. **沉默保温**：只在沉默阶段 4（>72h）兜底。

两个问题：

- **不完整**：她说完一句、对方一直没回，她不会像真人那样「过一会儿补一句」；冷场几小时想开个新话头，也没有独立链路，只能等生活流碰巧触发。
- **黑箱**：`processProactive` 返回 `null` 时日志也跟着丢了，`/why` 只能解释「她为什么这样回」，解释不了「她为什么这几天没来找我」。

v0.4.0 把主动拆成**四条独立可关的链路**，并且**每次心跳都留下决策与原因**。

## 2. 四条链路

按优先级从上到下；命中第一条可用链路后掷骰子，没中就记 `probability_miss`（不降级到下一条——「正在等回话」的窗口里不该突然变成「分享生活」）。

| 优先级 | 链路 | 触发条件 | 概率 | 门槛 | 说话姿态 |
|---|---|---|---|---|---|
| 1 | `follow_up` 没人接话补一句 | 她最后一句是会话最后一条，且已过 **20 分钟～3 小时** | 55% | 亲密度 ≥ 2 | 不追问、不催、不连发，一条就够 |
| 2 | `silence_revive` 沉默保温 | 沉默 > 72h（或沉默阶段 4）且真的安静 ≥ 6h，**一轮失联只问一次** | 75% | — | 语气收着，不质问、不抱怨 |
| 3 | `life_share` 生活流分享 | 因果链 9 / 天气 7 / 情绪 5 / 时段 4 有候选 | min(75%, 优先级/10) | — | 从具体的生活事件说起 |
| 4 | `open_topic` 冷场开话题 | 冷场 **3～72 小时**，这轮冷场里没开过话头 | 40% | 亲密度 ≥ 2.5 | 具体的小事开口，不用「最近咋样」 |

窗口边界是刻意这样切的：`follow_up` 过了 3 小时就交给 `open_topic`（等回话变成冷场），冷场超过 72 小时交给 `silence_revive`（关系重启而不是聊闲篇）。

## 3. 护栏（比链路更重要）

| 护栏 | 值 | 目的 |
|---|---|---|
| 单日上限 | 4 条 | 不刷屏 |
| 两次主动最小间隔 | 30 分钟 | 不连发 |
| 连推收手 | 对方不回时，**一天内主动 2 条就停**（>24h 可再试一次） | 真人不会一直发 |
| 失联重启只一次 | 一轮失联只问一次，对方回话后重置 | 不反复追问 |
| 每个窗口一次 | 一次冷场里 `follow_up` / `open_topic` 各最多一次 | 不重复开话头 |
| 说话权 | 会话最后一条是**对方**说的 → 不做主动（该她回复，走正常管线） | 不插话 |
| `/pause` | 立即停（仍正常回复） | 用户可控 |
| 免打扰 | 仍由消息门裁决（默认 02:00–07:00 延迟） | 深夜不打扰 |

**已知限制**：深夜被消息门延迟的主动冲动不会自动在早上重发（旧行为，未改）。好处是不会浪费 LLM 调用（门控在生成之前），坏处是这一次冲动就没了；需要的话可以把「延迟」接成待发队列，属于后续工作。

## 4. 配置

`config.yaml`（全部可选，不写就是四条全开）：

```yaml
proactive_channels:
  follow_up: true        # 没人接话补一句
  open_topic: true       # 冷场开话题
  life_share: true       # 她自己的生活流
  silence_revive: true   # 好几天没联系的重启
```

- 写错链路名/不是布尔值 → 启动时直接报错，不会「以为关了其实没关」。
- `KAREN_PROACTIVE_CHANNELS=off`：一次性全关（调试 / A/B 用）。
- `KAREN_PROACTIVE_VERBOSE=1`：把每次心跳的完整决策日志打到控制台（默认只写 debug 日志）。

## 5. `/why`：她为什么没主动找你

`/why` 原本只解释「上一轮为什么这样回」。现在多一段（下面是格式示例，具体原因由决策/门控实时给出）：

```
【她最近怎么决定要不要主动找你】
- 18:30 跳过 · 没人接话补一句：她刚说完，还不该催
- 18:15 触发但没发 · 冷场开话题：几小时没说话了，我想主动找个话头（消息门延迟：这个点她该睡了）
- 17:45 发送 · 生活流分享（我这边生活里有点事，想到了你）
提示：主动消息受「单日上限 / 两次间隔 / 链路开关 / 亲密度 / 沉默时长」共同决定。
```

三点设计取舍：

1. **原因用「当下沉默窗口里最相关的链路」**给出。冷场 4 小时如果报「补话窗口已过」，用户看不懂；现在报的是「冷场开话题：还差 N 分钟」。
2. **「触发但没发」单独标注**：决定了要发、被消息门挡住时不会显示成「发送」。
3. **只留最近 5 条**，且不复述对话正文（隐私）。

## 6. 模拟验证（可复现）

```bash
node node_modules/tsx/dist/cli.mjs scripts/proactive-sim.ts
node node_modules/tsx/dist/cli.mjs scripts/proactive-sim.ts --no-open-topic
```

时间线：第 1 天对方聊了两轮后消失、第 3 天回来一次、之后 4 天不回；心跳 15 分钟一次，共 7 天。

四条全开时的真实输出（节选，`seed=20261020`）：

```
10-20 09:15  不发  没人接话补一句：她刚说完，还不该催
10-20 09:30  发    我上一条还没回音，隔了一会儿想补一句     ← follow_up
10-20 10:15  发    我上一条还没回音，隔了一会儿想补一句     ← 对方 09:40 又说过话，新窗口
10-20 10:45  不发  没人接话补一句：这轮冷场里已经补过一句
10-20 13:15  不发  冷场开话题：这次随机没选中（概率 40%）
10-20 14:00  发    我这边生活里有点事，想到了你             ← life_share（优先级高于 open_topic）
10-20 14:30  不发  已经主动 2 条都没被回，先等等（隔天再说）
10-21 14:00  发    几小时没说话了，我想主动找个话头         ← open_topic
10-22 09:00  不发  对方刚发过消息，这一轮轮不到她主动
10-26 04:00  发    好久没联系了，我有点在意，想问问         ← silence_revive（一轮失联只一次）
```

按天统计：`10-20: 3、10-21: 1、10-22: 2、10-23: 1、10-25: 1、10-26: 1、10-27: 1`；
链路分布：补一句 3、生活流 4、冷场开话题 2、沉默保温 1。

**这个模拟暴露了两个真 bug（已修）**：

1. **她自己补的那句被当成新窗口**：补话窗口原来按「她最后一条消息」比较，于是她补完一句会把自己补的话当成新冷场，接着补第二句（像刷屏）。改为按**对方最后一次说话**计时。
2. **沉默保温每天重复触发**：旧实现有 `restartSent`「一轮失联只发一次」的保护，新模块一开始漏了，模拟里 10-26、10-27 连续两天发「好久没联系了」。已补 `silence_revive_already`。

关掉 `open_topic` 后（`--no-open-topic`）：冷场不再开话头，`life_share` 从 4 增至 5、`channel_off` 497 次跳过，证明链路开关是真实生效的，不是摆设。

## 7. 真实链路冒烟（会花一点钱）

离线模拟只能证明决策时序，不能证明「她真的能说出像样的话」。所以另有一个冒烟脚本，用**真实 DeepSeek** 走完整 `processProactive`：

```bash
node node_modules/tsx/dist/cli.mjs scripts/proactive-smoke.ts            # 补一句场景
node node_modules/tsx/dist/cli.mjs scripts/proactive-smoke.ts open_topic # 冷场 4 小时
node node_modules/tsx/dist/cli.mjs scripts/proactive-smoke.ts silence    # 失联 4 天
```

全部数据写在临时目录（`KAREN_DATA_DIR`），不碰 `data/`；单次约 ¥0.0003。

实测结果（2026-10-20，本机）：

| 场景 | 实际链路 | 她说的话 | 观察 |
|---|---|---|---|
| 她 30 分钟前说完、对方没回 | `follow_up` | 「我刚发现五花的猫粮快没了 / 它最近掉毛掉得我怀疑它要秃了」 | 两条气泡、没问「在吗」、没催，从自己的小事补了一句 ✓ |
| 冷场 4 小时 | `life_share`（时段触发，优先级高于 `open_topic`） | 「今天休息，在家瘫着呢」 | 一条、具体、不空泛 ✓ |
| 失联 4 天 | `silence_revive` | 「对了 五花今天掉毛掉得吓人 / 我扫了三遍」 | 语气收着、没有质问 ✓（但也确实没提「好几天没联系」——这是"装作没那么在意"的设计取舍） |

成本/延迟（`follow_up` 那次）：prompt 1830 / completion 21 tokens、缓存命中 1664、930ms、¥0.000283。

> 冒烟只跑 1 次/场景，不能当质量结论；它的作用是确认「链路 → 提示词 → 真实模型 → 气泡」这条代码路径是通的。

## 8. 没做的

- **群聊插话/潜水模型**（群聊里什么时候接话）：本轮只做私聊主动链路，群聊仍是「@ 才回」。
- **按用户自定义频率**：仍是全局配置。
- **真正的多轮主动性规划**（今天想找他聊什么、隔多久再问）：还是逐次决策 + 护栏。
- 夜间冲动不重发（见第 3 节限制）。
