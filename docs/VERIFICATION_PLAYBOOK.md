# 验证手册（Verification Playbook）

> 这份文档回答一个问题：**代码"看起来接线了"和"真的生效了"之间，怎么用最低成本验证？**
>
> 来源：v0.8.13–v0.8.19 连续 6 轮真实链路验证，**每一轮都在"单测全绿、离线模拟全绿"的情况下
> 抓到真 bug**。这不是偶发，是方法决定的：单测只覆盖纯函数，编排层、截断、幂等、开关组合
> 只在"真跑一次"时暴露。
>
> 目标读者：之后任何改这个项目的人（包括 AI 代理）。新增/修改功能时，按第 4 节的清单走一遍。

---

## 1. 六层验证（成本从低到高）

| 层 | 工具 | 成本 | 能抓到什么 | 抓不到什么 |
|---|---|---|---|---|
| ① 单测 | `npm test` | 零 | 纯函数逻辑、格式、边界 | 编排层、数据流、真实模型行为 |
| ② 离线评测守门 | `npm run eval:offline` | 零 | 记忆/锚点**指标**是否掉了 | 指标之外的一切 |
| ③ 离线模拟 | `npm run initiative:sim` | 零 | 决策**时序**（啥时候发/不发） | 说的话质量、编排 bug |
| ④ 真实链路冒烟 | `npm run *:smoke` | ¥0.002–0.005/次 | **编排层 bug**、阈值/权重、截断、断链 | 真实用户场景的随机性 |
| ⑤ 桥接 E2E | `npm test`（`bridge-e2e.test.ts`） | 零（fake 模型） | 桥接行为、多用户隔离、媒体链路、幂等 | 真实模型输出质量 |
| ⑥ 真机复盘 | `npm run qq:watch -- --once --since …` | 零 | 真实对话里的问题（复读、编造、延迟） | 自动化（需要人聊） |

**规则**：低于 ④ 的层全绿，不代表功能生效。v0.8.15 的教训——锚点路径"单测全绿"，
真跑一次发现**至亲离世记不住**（权重 0.60 < 阈值 0.75）。

## 2. 已交付的验证工具（全部可复现）

```bash
# 零成本，CI 跑
npm run eval:offline     # 记忆 40 条 + 锚点 30 条指标守门
npm run initiative:sim   # 主动消息决策时序（一天 × 四种关系热度 + 产品红线）
npm run test:e2e         # mock-OneBot 桥接 E2E（含表情包采集/出站、延迟补发、多用户隔离）

# 真实模型，手动跑（合计约 ¥0.015/轮全跑）
npm run anchor:smoke     # 锚点创建：该记的记住 / 闲聊不乱记 / 会注入      ~¥0.005
npm run digest:smoke     # 日记忆生成：事实不丢 / 同日幂等 / 92 条对抗     ~¥0.002
npm run refine:smoke     # 锚点复筛：精度优先 / 当日幂等                  ~¥0.003
npm run proactive:smoke  # 主动消息 plan 场景：像不像念稿                 ~¥0.002
# 零成本
npm run rollup:smoke     # 周汇总：7 天全覆盖 / 话题不被截断 / 幂等
npm run image:smoke      # 本机生图：真出图 / 可复现 / 落盘 / 产品路径（需先 image:start）
npm run asr:smoke        # 语音识别：TTS(SILK)→解码→ASR 往返 / WAV 直通 / 降级（需先 asr:start）
npm run asr:robustness   # ASR 鲁棒性：语速/口音/噪声 → CER（零成本，约 80 秒）
node node_modules/tsx/dist/cli.mjs scripts/mock-onebot-longrun.ts \
  --scenario voice --turns 4 --voice-in   # 语音入站长跑：真实 SILK 入站→ASR→记忆→回问（约 ¥0.02）

# 真机（需要真实 QQ 有历史消息）
npm run qq:watch -- --once --since 2026-10-18T00:00:00
```

脚本约定：全部用临时 `KAREN_DATA_DIR`，不写仓库 `data/`；退出码 0/1，可直接进 CI。

## 3. 真实链路冒烟写作模板

```ts
const tmp = fs.mkdtempSync(path.join(os.tmpdir(), "karen-xxx-smoke-"));
process.env.KAREN_DATA_DIR = tmp;
await import("dotenv/config");                 // 之后才能加载读 env 的模块

const { getVectorDb } = await import("../src/data/vector.js");
const { ensureMemoryV2Schema } = await import("../src/data/memory-v2.js");
const db = getVectorDb();
ensureMemoryV2Schema(db);

// 1) 造真实形状的输入（文本长度/时间格式要和真实数据一致）
seed(db);

// 2) 调**生产函数**（不要复制逻辑；复制了就测不到真实代码）
const result = await runTheRealThing({ db, chatFn: realLlmCall });

// 3) 断言"产品语义"，而不是"函数返回值"
//    - 该记的记住（召回下限）
//    - 不该记的别记（精度优先）
//    - 幂等（重跑不重复、不多花调用）
//    - 长度/预算（截断不能吃掉关键内容）

fs.rmSync(tmp, { recursive: true, force: true });
```

### 断言设计三条原则

1. **断言产品语义，不断言实现细节**。例：不是"返回 3 条"，而是"值得记的 3 条都在、闲聊 0 条"。
2. **必测反例**。只测"该发的时候发了"不够，要测"不该发的时候没发"——
   v0.8.18 就是靠"给 7 天各 100 字"的对抗用例才发现截断 bug。
3. **必测幂等**。同一份数据跑两次：第二次要么 `already_done`，要么不产生重复/不多花调用
   （v0.8.17 在这里挖出 3 个缺口）。

## 4. 新增/修改功能时的验证清单

- [ ] 纯逻辑抽成纯函数 + 单测（含边界与反例）
- [ ] 若影响记忆/检索指标 → 跑 `npm run eval:offline`
- [ ] 若是决策逻辑（发不发/什么时候发）→ 加进 `initiative:sim` 或对应模拟
- [ ] 若是"编排层"（读 DB → 拼文本 → 调模型 → 写 DB）→ **写一条真实链路冒烟**
- [ ] 若涉及桥接/消息收发 → 加进 `bridge-e2e.test.ts`（fake 模型，零成本）
- [ ] 凡是"截断/预算"相关 → 用**上限量级**的数据测（如 7×100 字、92 条消息）
- [ ] 凡是"写了数据"的路径 → 确认**有人读**（v0.8.18 教训：周汇总写了半年没人读）
- [ ] 凡是"判定后要记住结论"的路径 → 回写标记，别只靠 job_runs 一行记录
- [ ] 报告数字只报**区间与条件**，单次结果不当结论

## 4.5 三个踩过的坑（写冒烟/ E2E 时一定会遇到）

### 坑 1：`vi.spyOn(Math.random)` 控制不了子进程

桥接 E2E 里 bridge 是**独立进程**。在测试进程里 mock 随机数只影响测试自己，
桥接仍按真实概率行为（例：可能"顺手"再发一张内置贴纸）。
→ **写断言时要等"目标事件"出现，而不是"第一个事件"**；
   v0.8.19 的贴纸断言就因此 flake 过一次（第一版拿到的是内置贴纸）。

### 坑 2：fire-and-forget 写入要轮询，不能立即断言

表情包采集、记忆写入都是异步的。发完消息立刻查库会偶发失败。
→ 用 `pollDb(read, ok, message)`（E2E 里已有）或自己写 50×150ms 轮询；
   失败信息里带上最后读到的值，排查更快。

### 坑 3：造数据必须走生产写入路径

直接 `INSERT INTO t2_episodes` 会**绕过 `insertEpisode` 里的 FTS 索引维护**，
结果是数据在表里、检索 0 命中，测试会误判"检索坏了"（v0.8.21 写 retriever 测试时踩到）。
→ 用 `insertEpisode()` / `upsertDailyDigest()` 等生产函数造数据；人设用 `setCurrentPersona()` 切。

### 坑 4：E2E 交互不要只等"目标事件"，先等"本轮回复"

全量并行时桥接进程处理变慢，直接等某个附带动作（如贴纸）会假失败——
v0.8.19 的贴纸断言就因此在全量跑里失败过两次。
→ 先 `waitFor` 这一轮的回复出现（说明消息处理完了），再等附加动作。
另外：全量并行跑时桥接子进程会被 CPU 抢占，**等待默认 30s**（个别场景 20s 会偶发假失败）。

### 坑 5：下载大模型要先确认「走的是哪条 CDN」

`huggingface_hub` 1.x 默认走 **Xet**（`us.aws.cdn.hf.co`）；HF 直连不通时它不会自动回退 HTTP，
报的是 `RuntimeError: Task error: File reconstruction error: CAS Client Error`。
→ 设置 `HF_HUB_DISABLE_XET=1` 或改用镜像 + 分块 curl；并注意 `| tail` 会把失败吞成 exit 0。

### 坑 6：验证入站媒体要用「真实编码形态」，别用方便格式直通

v0.9.0 的 ASR E2E 直接喂 WAV，结果**SILK 解码分支从没被端到端覆盖**——而 QQ/NapCat 下发的是 SILK。
→ 测试里用真实编码器（silk-wasm）生成 SILK 下发，并断言服务收到的是「解码后的 WAV」，
  否则"链路通了"只是测试自己绕过了最难的一段。

### 坑 7：临时目录的异步任务会在 cleanup 后报错

冒烟脚本 `fs.rmSync(tmp)` 之后，后台的 embedding 升级/成本写入还在跑，
会刷 `database connection is not open` 噪声日志。
→ 脚本结尾**不要主动 `db.close()`**，直接退出进程即可（进程退出=连接释放）。

## 6. 什么时候可以不做真实冒烟

- 改动只涉及纯函数（并且已有单测覆盖）
- 改动只涉及文案/提示词（但要有 prompt 断言测试锁住关键句）
- 改动是"加日志/加返回字段"（无写入副作用）

其余情况——尤其是**读写数据库、调模型、跨模块拼接**——都应该至少跑一次真实链路。

## 7. 维护约定

- 新增 smoke 脚本：放 `scripts/*-smoke.ts`，在 `package.json` 加 `xxx:smoke`，
  并更新本文第 2 节与 CHANGELOG。
- 本文档里的每个命令都由 `docs-consistency.test.ts` 校验：脚本文件必须存在、
  npm 脚本必须存在（防止文档写了不存在的工具）。
- 冒烟脚本产生的费用写进 CHANGELOG，别让"验证"变成不知道花了多少钱的黑盒。
